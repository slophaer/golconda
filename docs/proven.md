# What is proven

Each row names the test that proves a claim. The design pages say why. A marker is a line that
`scripts/boot-test` prints (`PASS: <marker>`). It runs the image in QEMU with OVMF
([Boot test](reference/boot-test.md)). A check is a Nix output or a script that `scripts/lint` or
`scripts/verify` runs.

The last column names the line of `tests/boot/matrix` that prints the marker, by its flags after
`--secure-boot --ssh-test --tpm`, without `--timeout`. The first line has no other flag. A line that
does not start with these flags is shown whole. `@image=ATTR` boots another image, and `@next` is
its next release. `scripts/verify` boots every line by default. For a check, the column names the
command that runs it.

## Not proven

- **Runs by hand only.** No marker or check repeats these runs. The
  [Hetzner Cloud guide](reference/hetzner-cloud.md) ran on a `cpx12`, with and without `/imds`, with
  an update over HTTPS and a fallback. `golconda release build` built two releases with a new
  `scripts/make-keys` set. Both booted, the second as an update, and no private key of the set was
  in the store afterwards. A release signed on the host was the same as one signed in the sandbox. A
  boot without `rw` on the kernel command line does not reach `multi-user.target`.

- **imdsd over IPv6.** No run has imdsd reach an IPv6 endpoint, because QEMU serves none.

- **Other build hosts.** No test builds on hosts with different build file systems. No test builds a
  whole release twice from the same inputs and compares the two.

- **Enrolment on real firmware.** The harness enrols keys offline in the variable store, or lets
  systemd-boot enrol them in OVMF (`--auto-enrol`). Not run on hardware: clearing the keys in a
  firmware's setup, systemd-boot's 15-second warning (`force` on hardware), that firmware accepting
  the four files and ending Setup Mode, option ROMs (graphics, network, storage) running after an
  enrolment with Microsoft's keys, and adding `db.crt` beside a vendor's keys. Hetzner Cloud has no
  Secure Boot.

- **Hardware.** Only QEMU with OVMF on x86_64 has run, and Hetzner Cloud's QEMU with EDK II. aarch64
  is postponed ([Scope: Later](design/scope.md#later)), because no aarch64 package can be built
  here.

- **Loader recovery by hand.** A loader that no longer starts, a lost ESP and a lost `db` key
  ([Boot loader: Recovery](design/bootloader.md#recovery)) have no marker. The rotation run has two
  releases, so it leaves out step 5 of the rotation.

- **A key on a real token.** The `db` and PCR keys on a token, and the host CA key that
  `golconda vars certify` signs with (`cli/tests/cli.rs`), are proven with SoftHSM only. No run on a
  YubiKey. The YubiKey's packages (`pcsc-lite`, `ccid`, `yubico-piv-tool`, `yubikey-tools`) are
  tested without a token (`tests-yubikey-tools`: the module loads and finds no slot). The release
  key on a token *(later)*.
