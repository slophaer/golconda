# The v1 checklist

v1 is done when every item under [Prove](#prove) and [Build](#build) is checked. Each item names the
test that checks it. [Scope](design/scope.md) says which features v1 has;
[What is proven](proven.md) lists the boot-test markers that pass today. This page is the gap
between them. Items marked *(proposed)* wait for the owner's decision.

## What v1 means

A v1 image can run a real server unattended:

- an operator can log in with a certificate, and nobody can log in without one;
- an update installs, and a bad one rolls back, with no secret lost on the way;
- the secrets a machine needs reach it without being in the image;
- all of this has run at least once outside QEMU.

## Prove

These exist in the code and the docs, but no test checks them.

- [ ] **Unseal after an update.** The next release unseals the sshd host key without re-sealing it,
  and so does the previous release after a fallback. Test: new markers in
  `scripts/boot-test --secure-boot --tpm --ssh-test --next`, and with `--fail-health`.
  ([Measured boot](features/measured-boot.md#status))
- [ ] **Certificate login.** A user certificate signed by the CA in `TrustedUserCAKeys` logs in with
  an allowed principal; a revoked certificate (in the KRL) and a wrong principal are refused; the
  host presents its host certificate. Test: boot-test markers.
  ([SSH login](features/ssh-login.md#status))
- [ ] **An admin var end to end.** The host certificate and the KRL are pushed, sealed on the
  machine, read by sshd, and survive a reboot. Test: a boot-test marker; needs the
  [deploy tool](#build). ([Vars](features/vars.md#status))
- [ ] **IPE denies a copy.** A binary copied to `/var` gets `Permission denied`, with the IPE audit
  record. Test: a boot-test marker. ([Execution policy](features/execution-policy.md))
- [ ] **hwdb from `/base`.** The image built after `7438a3f` passes the `hwdb` marker.
- [ ] **One run outside QEMU** *(proposed: Hetzner Cloud)*. Write the disk, enrol or provision,
  boot, log in with a certificate, install the next release over HTTPS, roll back once. Test: the
  [Hetzner guide](reference/hetzner-cloud.md) run step by step, its *(planned)* removed, the results
  recorded in [What is proven](proven.md).

## Build

- [ ] **The vars deploy tool** (`golconda-vars`): keeps admin vars age-encrypted on the deploy host,
  pushes them over ssh, and has the machine seal them; rotation is "push again".
  ([Trust: Secrets and vars](design/trust.md#secrets-and-vars))
- [ ] **A first-boot enrolment unit before sshd**: generates the host key, gets its certificate and
  the KRL, then lets sshd start. Without it a certificate-only machine needs two deploys.
  ([Trust: Identity](design/trust.md#identity))
- [ ] **A release script** that refuses a version that does not increase, on the builder.
  *(proposed: v1, because a reused version installs nothing and says nothing)*
  ([Updates: Versions](design/updates.md#versions))

## After v1

Wanted, but not needed for v1:

- `golconda diff` ([Configuration: Diffing](design/config.md#diffing-planned));
- automatic Secure Boot enrolment (manual enrolment works);
- the p11-kit CA store with anchors and a distrust list
  ([Trust: CA store](design/trust.md#3-ca-store)) *(proposed: after v1; the Mozilla bundle covers a
  server that talks to public services)*;
- keys given as a string path through `extra-sandbox-paths`
  ([Build host: Keys in the sandbox](reference/build-host.md#keys-in-the-sandbox)): the path form
  works today;
- systemd-imds for cloud metadata;
- loader recovery by hand and a boot without the `db` enrolled
  ([Boot loader: Recovery](design/bootloader.md#recovery)): documented, no marker;
- everything [Scope](design/scope.md#after-v1) lists after v1.

Internal work that does not change what v1 is: a build daemon run as a service, and splitting
`scripts/boot-test`.
